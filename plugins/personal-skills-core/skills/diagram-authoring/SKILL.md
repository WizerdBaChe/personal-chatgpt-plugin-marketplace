# diagram-authoring

Select sketch, document figure, standalone view, editable deck or reconstruction audit by the deliverable. For a whole-codebase completeness obligation, start with code-review-deep-checklist B; this skill produces views and declares omissions.

List source inputs. Every node, edge and label traces to evidence or is visibly assumed. Write the structural model first (nodes/edges, state-event matrix or participants). Choose one primary view per question using [representation models](../product-design-thinking/references/representation-models.md); check [view integrity](../product-design-thinking/references/view-integrity-checks.md).

Render using [notation precision](references/notation-precision.md) and [carrier playbook](references/carrier-playbook.md). Mermaid suits small automatic-layout sketches. SVG or native PPTX shapes support geometry whose placement conveys meaning. Use Presentations for PPTX mechanics, visualize for interactive in-conversation explanations and Sites for website deliverables when applicable.

Verify structure by parsing output, geometry by bounds/anchors/overlap measurements, and appearance by inspecting a render. Report which checks actually ran. User acceptance and agent visual inspection are different evidence. Deliver editable/regenerable source, legend and specific gaps. Reconstruction views name drawn and excluded lifecycle/component/sequence/decision views; do not imply inventory coverage from a visually complete page.
